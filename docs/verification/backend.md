# Backend acceptance runner: fixture/subset evidence

`scripts/acceptance/backend.py` is an executable acceptance entrypoint, with an explicit incomplete gate. It executes `scripts/smoke.py --static` against the provided **built executable**, then real owning-crate integration targets for OAuth, CSRF/ownership, writes/retries, signed external mutations, follows/feed, statistics/deletion, disconnect/export, durable views, backup/restore and shutdown. Every target must exit zero, execute nonzero tests, and report each required named case as passed. A missing, filtered, ignored or disabled required case fails. It preserves individual logs and `report.json` with the executable SHA256, executed/ignored/filtered counts and `fixtureOnly=true`. Ignored child entrypoints retain their own count and do not contribute to executed tests.

```sh
python3 scripts/acceptance/test_backend.py
python3 scripts/acceptance/backend.py target/x86_64-unknown-linux-musl/release/atmusic --fixture-only --output work/acceptance/backend
```

The explicit `--fixture-only` command can exit zero for that executed subset. Omitting `--fixture-only` runs the same evidence collection and then exits **2, blocked**, because the complete packaged flow/recovery journey and dedicated live matrix are unexecuted. Disabling a required target exits nonzero before executing a binary, for example `--skip-target atmusic-server/oauth_security`. The runner also records the live inventory validator result for the exact artifact, but completed inventory metadata cannot substitute for actual live execution.

The final 2026-10-06 candidate run passed 190 executed Rust tests across 35 targets and all 148 required named cases, with zero filtered cases and one excluded child-helper entrypoint. All three fixture validators and static smoke passed. The exact artifact is `34e351ad18658732cddd13668af3ae969ea6e4a85dcb80d0f6cccfd86083b666`; the [candidate receipt](backend-candidate.json) records the source binding and blocked complete packaged/live gates. The 190 tests are a selected rerun from the 331-test workspace check, not an additional distinct-test count.

Before the host targets, the runner executes the three independent M5.4.1 fixture validators: `fixture_integrity`, `manual_expectations` and `time_reproducibility`. These check every frozen row's schema and binding, four-window artist/track/album ranking tables, and nine injected host-day/timezone combinations. Corruption controls verify that changed identity/state/timestamps and expected values cannot pass. Validator cases remain a separate count from executed Rust tests.

Scope matters: the Rust integration targets exercise the host-built server/router, isolated SQLite databases, actual worker logic and signed repository fixtures, with fake DNS/HTTP only at the upstream boundary. They are **not** the musl executable serving the complete OAuth/write/relay journey. `deployment` includes real CLI migrate/serve/backup/restore tests of the host executable. The static packaged smoke establishes ELF self-containment, configuration safety, initialized readiness, empty history reads, embedded assets, JSON errors and clean SIGTERM from a fresh temporary directory.

The `packaged_flow` complete journey and `packaged_recovery` kill-after-remote-write/restart/exactly-one-record journey remain unexecuted. Production worker initialization and resolver-bound current-head verification need their own required host targets, followed by a rebuilt executable; a prior artifact cannot prove later source changes. A host `crash_after_remote` fixture does not close `packaged_recovery`. The live OAuth/local-write/external-write/follow/stats/delete/restore matrix also requires dedicated identities, namespace ownership, public HTTPS and independent PDS/relay evidence. This entrypoint records executed evidence without declaring M6.4.2, M6.4.3 or the M7 start gate complete.

To implement the missing packaged journeys, the harness must drive the actual release CLI through upstream endpoints that pass its production HTTPS, global-IP DNS, issuer, DPoP, signature and current-head checks. The CLI has no injected transport or TLS/DNS bypass. Local host fixtures use dependency injection at the upstream boundary and cannot replace this executable evidence. Controlled public fixture infrastructure, with valid TLS and identity metadata, remains a prerequisite for an ordinary release executable; neither an application test flag nor a fixture-only rebuilt artifact can stand in for the published artifact.

| Missing case | Required actions and observable evidence |
| --- | --- |
| `packaged_flow` | Start only the supplied static executable from an empty temporary directory. Complete actual OAuth callback, session and CSRF exchange; reject wrong-origin/owner requests before an upstream call; publish a scrobble, observe retry and reconciliation, then confirm remote URI/CID and public history/feed/statistics. Ingest an independently authored signed external record, publish/list a follow, delete and verify remote absence plus hidden local views, export only the owner account and disconnect without a public-erasure claim. Record each checked result and a nonzero executed count against one artifact SHA256. |
| `packaged_recovery` | Let the controlled upstream persist a write while holding its response before ACK. SIGKILL only the harness-owned static child, restart the same database and reconcile the exact operation/rkey without a duplicate remote record. Check history/feed/statistics, operation attempts and durable repository checkpoint. Run the same executable's backup/restore CLI into a new directory, restart with the original encryption key, and prove the same rows, state and checkpoint. Corrupt input and missing/wrong-key controls must fail without changing the old instance. |
| `unrun_gate` | Removing either required packaged journey must fail explicitly and name the omitted case. Process startup, an HTTP 200, a complete metadata inventory or an ignored test cannot count as a completed journey. |

The upstream fixture needs a bounded control channel for commit-before-response pauses, retry responses, valid signed repository snapshots, exact current-head advancement and independent record lookup. These controls belong to the upstream harness. All owned child processes and pause gates must be released during teardown; failures must preserve sanitized logs and fail the runner. These are implementation requirements for the missing harness, not records of executed cases.
