## Rollback procedure (only after gates and approval)

For an additive compatible upgrade, the local helper can atomically point `current` to a retained prior `releases/<commit>-<archive-digest-prefix>` only when the operator supplies independently trusted SHA/commit/tag identities for both the target and current releases. That operation changes only the symlink; it does not restart `atmusic` or its socket, verify unit provenance, check schema compatibility, or establish health. Production rollback therefore remains gated on a separately reviewed installer/runbook that performs the approved service restart and health checks. Do not restore the pre-upgrade backup to roll back code: doing so could reintroduce revoked credentials or lose acknowledged writes. If the migration is not backward-compatible, rollback by link switch is unsafe; stop and request an explicit disaster-recovery decision before proceeding.
