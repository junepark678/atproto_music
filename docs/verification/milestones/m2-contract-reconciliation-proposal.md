# M2 OAuth and identity contract reconciliation — review-only proposal

**Status: DRAFT FOR OWNER / SECURITY REVIEW. Not published to GitHub.**

This proposal records known differences between the published M2 GitHub acceptance contracts and accepted ADR 0005 / current Node BFF behavior. It does not amend an issue, change runtime behavior, or recommend issue closure. All M1–M6 issues remain open; M7 is excluded.

The distinction is important: deterministic tests can demonstrate what the current Node implementation does, but do not silently supersede a published issue contract. Conversely, changing security policy to match an older contract requires explicit review and is not an automatic test-fix.

## Evidence wording to preserve

- The initiation-time issuer mismatch check and the callback-time DID/PDS/AS binding check are distinct boundaries.
- The 600-second state regression does not satisfy the unamended 299/300-second issue contract.
- The 30-day renewable app cookie does not satisfy a seven-day absolute cap.
- A rejected redirect is the current stricter Node behavior, not proof that the issue's three-redirect behavior was implemented.
- A local logout response, cleared cookie, or absent local session is not evidence that an upstream token was revoked. The local revocation journal does not retry remote requests.
- A 502 `oauth_upstream` with no session or accepted write is safe local rejection evidence, but does not satisfy the published 4xx expectation.
- Fake AS/PDS fixtures, subprocess recovery, local full-suite passes, dirty-tree test reports, and source hash comparisons are not hosted CI, independent live acceptance, browser acceptance, or release provenance.

## Review process suggested

1. Assign an explicit owner and security reviewer for #50, #51, #55, #57, #58 and #60.
2. Choose one disposition per contract conflict; leave behavior unchanged until a decision is recorded.
3. Update the issue and/or ADR, API contract, case map, tests, and operator-facing docs together, in separately reviewable changes.
4. For #61, first make a credential-safe current-Node driver and evidence schema; then authorize any live run against named disposable identities/servers with cleanup and release provenance.
5. Re-query issue state after review. No issue is considered resolved by this draft.
