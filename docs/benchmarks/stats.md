# Statistics benchmark and cache (node:sqlite on the Node host)

Generated by `scripts/benchmark-read-models.ts` from the report of `worker/test/bench/read-models.bench.test.ts` (environment in [read_models.md](read_models.md)). Each user's statistics (limit 10) are computed uncached at asOf = 2026-01-15T12:00:00Z through the production `statsWithCache` (a miss, which stores the body), then requested again 250 ms later: the exact cache may reuse the body only after its indexed EXISTS probes show that no row crossed either window bound (ADR 0004 §5.8). Every listen sits at a half-second, so the 250 ms shift is provably empty and the second request is a hit; the hit must equal a fresh uncached computation at the later asOf. Then the production `bumpStatsVersion` invalidates the body, and the next request must be a miss that again equals that computation. The miss is checked against an oracle computed in JavaScript from the generated records, not from SQL.

Every uncached statement that reads scrobbles must SEARCH `scrobbles_owner_time` or `scrobbles_stats` by DID (never SCAN scrobbles) on SQLite 3.54.1; in a 7d, 30d or 365d window every scrobbles search must be bounded by `did=? AND listened_at>? AND listened_at<?`, so the rows read stay proportional to the window. Uncached over all scales and windows: p50 5.93 ms, p95 449.22 ms (80 calls); cached hits: p50 0.01 ms, p95 0.04 ms (320 calls).

## Cache-hit probe budget: at most 4 statements for a window, 3 for `all`

The budget counts **every statement of the hit**, and each one must plan as an indexed SEARCH. A windowed hit reads the users row (`stats_version` and `generation`), the cache row and two EXISTS probes, one per moved window bound: 4. `all` has no lower bound, so it needs one EXISTS probe: 3. The suite asserts it in `stats cache hit within ADR Q10 probe budget and equals uncached result`.

Met: all 16 cached hits are within the budget.

Query plans: `worker/test/read/stats-plan.test.ts` pins indexed DID/time searches for every statistics and cache-probe statement over 100 × 1,000 seeded rows, with a negative control that drops the scrobble indexes; `worker/test/acceptance/query-plans.test.ts` covers M6.2.3 `slow_query_detection`.

## Reproduce

```sh
run_root="work/bench/m6-$(date -u +%Y%m%dT%H%M%SZ)"
npx tsx scripts/benchmark-read-models.ts --paced --require-visible-profile --no-docs --out "$run_root/visible-profile/read-models.json"  # visible cgroup checks only; attest host/hidden parents separately
npx tsx scripts/benchmark-read-models.ts --paced --no-docs --out "$run_root/paced/read-models.json"  # paced local measurement; not M6.2.3 acceptance
npx tsx scripts/benchmark-read-models.ts --no-docs --out "$run_root/unpaced/read-models.json"  # unpaced repository-gate run; never M6.2.3 acceptance
```
