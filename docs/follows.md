# Music follows

PUT and DELETE `/api/v1/follows/{did}` derive the actor from the authenticated cookie and require the same Origin and CSRF protections as other writes. A body and self-follow are rejected. The target DID hashes to the deterministic core rkey. Admission needs an initialized verified PDS worker; without one a new write returns `503 outbox_not_ready` and queues nothing.

Repeated pending requests for the same action return the same operation. An alternating action creates a distinct durable operation with references to all earlier pending edge operations. The worker admits it only after every predecessor becomes terminal, including failures. This persists across restart and preserves requested create/delete ordering without overwriting remote records.

Unfollow hides all known duplicates immediately and stores their complete bounded URI set, including pending predecessor creates and the canonical URI, under one operation. Partial remote removal remains pending. Completion requires each URI to be absent from one complete verified signed repository, followed by one atomic projection/operation update. A previously unknown matching remote duplicate prevents success with `remote_edge_changed`; the bounded target list is retained and no unrelated record is deleted. Deletion uses each verified CID as `swapRecord`; a changing remote record must be rechecked, and a follow that now targets another DID is retained with terminal `remote_record_conflict`.

Terminal failed DELETE replay returns `502 deletion_failed` and the original operation in `Location`, rather than a successful absence response. A fresh PUT may reconcile an existing verified matching canonical edge without changing its remote display timestamp. The failed canonical tombstone is cleared only when that verified create is acknowledged. Pending successor delete tombstones remain hidden throughout predecessor completion.

Followers/following pages serialize the lexicographically smallest active confirmed URI for each actor/subject pair. Counts use SQL distinct identities without a cap. Active actor and target checks, suppression and tombstones apply consistently to lists, counts and following feed membership. Pages bind the cursor to endpoint and DID, order by createdAt then full URI descending and apply the frozen exclusive continuation boundary. Reactivation stays hidden until a complete verified backfill converges.

Deterministic evidence: `cargo test -p atmusic-server --test follows_write --test follows_list --test follow_feed`. The fixtures sign genuine repository commits and exercise the production verification gate before SQLite projection, including crash recovery, duplicate removal, competing intents, partial remote removal, external mutation races and verified account reactivation. Live service and namespace gates remain separate.
